# HINT3 v2 routing evaluation — 2026-09-26

Kayak now evaluates real support queries, including out-of-scope requests, through
pinned HINT3 suites and explicit routing reports. A frozen Laya run beat the
word-overlap baseline on two domains but rejected many valid requests. These
results support the evaluation workflow and identify model/recipe weaknesses;
they do not establish readiness for automatic customer routing or SOTA quality.

## Frozen experiment

- HINT3 corrected v2 at `99965c892ea9a6801a87083d3861b0b04c91a4e7`.
  Official SOFMattress (397) and Curekart (991) test rows were evaluated once,
  in source order. No training, test-error-driven revision, or threshold tuning.
- Cached [convaiinnovations/laya](https://huggingface.co/convaiinnovations/laya/tree/55cf4c4ebb4ebe31b2550e8bdf3bd21b99753851) checkpoint revision `55cf4c4ebb4ebe31b2550e8bdf3bd21b99753851`,
  weights SHA-256 `891102d372688fc2a094dac56a384bc537b87c63f21f9f3dac0be2b7cbc8d86c`.
  Laya 0.3.20, Transformers 4.57.6, PyTorch 2.14.0; CPU FP32, AMP disabled,
  two compute threads, one interop thread, seed 7. No network/model downloads.
- Original text and the `hint3-label-text-v1` question reached inference. Only
  training labels define candidates; expected example labels stay outside calls.
  Candidate order is sorted intent IDs followed by `NO_NODES_DETECTED`.
- The exact tokenizer sequence was checked for every train/dev/test example,
  including all instructions, options, and state. Head budgets were increased
  from 192 to 250 (SOFMattress) and 334 (Curekart), with total budget 512. These
  preserve every token. Powerplay11 was loader/token-audited (head 734, total
  minimum 963), but was not included in this model run.
- Laya clamps the checkpoint's `choice:11+` temperature from 0.10058 to 0.5.
  The warning and applied runtime configuration were retained. Rejection scores
  are raw rounded `answers.intent.probabilities.NO_NODES_DETECTED`, unchanged and
  uncalibrated. The frozen protocol called that field `probs` in prose; the
  analysis records the actual wire key. No score renormalization occurred.

All 1,388 predictions completed without execution failures in 270.53 seconds.
The process-tree memory monitor sampled once per second: peak RSS was 2.14 GiB,
peak machine swap zero, and minimum available memory 7.27 GiB. Limits were
600 seconds, 6 GiB process RSS, 4 GiB machine swap, and 1.5 GiB minimum available
memory; no bound triggered. Samples do not capture instantaneous peaks. A first
supervisor launch failed before inference because sandbox process inspection
was unavailable; its terminated process, empty log, and receipt were retained.
The successful run used the same frozen protocol with process-inspection access.

## Observed quality

| Domain / system | Overall accuracy | Correct in-scope routes | OOS recall | OOS F1 |
| --- | ---: | ---: | ---: | ---: |
| SOFMattress / word overlap | 18.89% | 61/253 (24.11%) | 9.72% | 0.1647 |
| SOFMattress / always reject | 36.27% | 0/253 | 100% | 0.5323 |
| SOFMattress / Laya | 52.90% | 88/253 (34.78%) | 84.72% | 0.6455 |
| Curekart / word overlap | 14.33% | 91/459 (19.83%) | 9.59% | 0.1689 |
| Curekart / always reject | 53.68% | 0/459 | 100% | 0.6986 |
| Curekart / Laya | 59.54% | 113/459 (24.62%) | 89.66% | 0.7249 |

Laya falsely rejected 112/253 (44.27%) valid SOFMattress requests and 307/459
(66.88%) valid Curekart requests. Its routing precision, conditional on routing
rather than rejecting, was 53.99% and 54.59%; coverage was 41.06% and 20.89%.
This is why overall accuracy alone would give an incomplete picture.

| Laya score diagnostic | SOFMattress | Curekart |
| --- | ---: | ---: |
| OOS AUROC | 0.8040 | 0.7102 |
| OOS average precision | 0.6976 | 0.7071 |
| In-scope false-positive rate at 95% OOS recall | 74.70% | 77.34% |

These score curves do not select a deployment threshold. HINT3's training-derived
development split lacks OOS data; suitable independent development examples are
needed before tuning rejection. The checkpoint's pretraining exposure to HINT3
is unknown. A single fixed-order CPU run does not quantify variation across
recipes, models, seeds, devices, or future traffic.

Removing the eight normalized train-overlap Curekart test rows, without another
model call, yields 983 cases: 59.92% overall accuracy, 24.83% in-scope accuracy,
OOS F1 0.7288, and AUROC 0.7140. That separate sensitivity result leaves the
main conclusion unchanged. Official scores retain every row. Internal duplicate
texts and unobserved test intents remain explicit limitations; Wilson intervals
and paired tests rely on independence assumptions that these duplicates weaken.

## Verification and reproduction

The [workflow guide](../hint3-evaluation.md) documents preparation, suite export,
Python/CLI scoring, split identity, failure semantics, and metrics. The
[aggregate artifact](../../benchmarks/reports/2026-09-26-hint3/summary.json) retains
counts, rates, versions, model/dataset hashes, guard settings, and raw artifact
hashes. It includes source digests at inference time. A later finite-number error
boundary change does not alter these valid observations or their arithmetic.

Local evidence is under `validation/hint3-evaluation-20260926/`: frozen protocol,
token audit, model runner/supervisor, raw provider responses, prediction sets,
score maps, routing reports, complete paired benchmark reports, resource samples,
and an independent scikit-learn check on the actual model outputs. That check
agreed on accuracy, all-candidate macro F1, AUROC, AP, and FPR95 to `1e-12`.
Raw datasets, input texts, and per-case results are not bundled in this public
record. Their hashes establish file identity, not independent execution
attestation. Full reproduction requires the pinned data and checkpoint.

The checked-in metric fixture covers 43 independent scikit-learn cases. Analytic
checks separately cover missing predictions, empty populations, ties, malformed
scores, corrupt caches, grouped development, overlap sensitivity, and CLI file
boundaries. Existing API and model contracts remain unchanged. See the PR's
validation receipt for the final code checks; these are evaluator evidence,
separate from the model quality numbers above.
