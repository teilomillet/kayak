# Benchmark tooling audit

**This is an audit of the evaluator, not a model benchmark result.** The retained
model outputs are synthetic fixtures. No full-model accuracy, accelerator timing,
memory bound, or competitor advantage is established here.

The September 25, 2026 review began from commit `6fed569`. Separate automated
reviews examined artifact integrity, measurement, and dataset methodology,
then repeated the checks after reporting and validation fixes. The retained
fixtures and regression checks below provide the evidence for those changes.
This internal review does not establish external certification.

Use the [mock commands](../benchmark-protocol.md#run-now-no-model-or-gpu) to reproduce
the controlled scenarios. The same protocol prepares a later Mac/GPU run.

## Findings and corrections

| Challenge | Observation | Correction and regression evidence |
| --- | --- | --- |
| Alter saved predictions without changing winners | Structurally valid score/token edits could preserve summaries and pass the loader | Version 2 binds the full file for terminal artifacts and only the committed prefix for running checkpoints; edits or missing/extra bytes within that bound are rejected |
| Rewrite configuration during execution | A nested caller dictionary remained mutable; nonfinite JSON could become `null` | Metadata is validated before serialization and deeply copied before calls; NaN/Infinity and mutation cases are covered |
| Invent an impossible execution history | Negative memory, excessive warmups, multiple shortened rows, and terminal statuses without a supporting failure could load | Stronger counters and history invariants, tested alongside legitimate interruptions and memory stops |
| Time input copying as inference | A controlled 10-second copy plus a 2-second decision recorded 12 seconds | Defensive evaluator copying now precedes the timer; the mock clock checks the 2-second boundary |
| Fail while accelerator work remains pending | The post-call synchronization was skipped on decision failure | Completion hooks run after failed calls and interrupts; original errors remain meaningful |
| Claim speedups with unknown execution | Custom adapters, incomplete local hardware metadata, and custom synchronization could be misleading | Ratios require known local timing provenance; HTTP/custom/legacy/unknown paths retain raw durations without a speedup |
| Hide experimental factors | Batch size and source changes were not fully visible in comparison output | Actual batch size, both environments/configurations, and source/model/precision changes are disclosed |
| Treat equal missing MPS properties as equal hardware | Two absent GPU core counts passed the first revised comparator | MPS device identity now requires a known positive core count; missing/ambiguous inventories withhold a speedup |
| Apply a caller memory guard to a hidden server | A custom wrapper could bypass the HTTP memory restriction | The guard requires a known local `Model`; caller memory cannot establish remote model memory |
| Describe normalized text as duplicate-free | Exact strings are unique, but case/whitespace/punctuation normalization finds overlaps | Preserve official splits and publish IDs, labels, counts, and normalization rules below |
| Overstate retained interruption evidence | Two entered calls can leave only one completed attempt | Markdown says recorded attempts and explicitly discloses an interrupted call's missing result/duration |
| Overstate synchronization in Markdown | A local model with a caller-supplied no-op hook received an overly broad timing description | Reporting uses recorded synchronization scope and describes custom completion as unverified |
| Leave the future run instructions unexecutable or incomplete | `uv sync` creates an untracked lockfile; setup failure can precede any report directory; plain package inventory can inspect a different active environment | Commands preserve source cleanliness, name the project interpreter, and separately retain stdout, stderr, and exit status |

The executable regressions live in
[integrity tests](../../tests/test_eval_integrity.py),
[measurement tests](../../tests/test_eval_measurement.py),
[report tests](../../tests/test_eval_report.py), and
[dataset audit tests](../../tests/test_dataset_audit.py).
The second review found the MPS and report-wording issues above; they were fixed

## Dataset inspection

The audit reads the exact pinned BANKING77 files from a prepared cache. It does
not call a model, download implicitly, filter examples, or alter labels. Its
three diagnostics are:

- `exact`: literal text equality.
- `casefold_whitespace`: `" ".join(text.casefold().split())`.
- `unicode_word_tokens`: `" ".join(re.findall(r"\w+", text.casefold()))`.

The final rule removes punctuation boundaries and can conflate different
meanings. These are matching-text heuristics, not an exhaustive semantic audit.

| Diagnostic | Train/dev row pairs | Train/test row pairs | Dev/test row pairs | Duplicate groups within test |
| --- | ---: | ---: | ---: | ---: |
| Exact | 0 | 0 | 0 | 0 |
| Casefold and whitespace | 0 | 7 | 0 | 1 |
| Unicode word tokens | 3 | 23 | 2 | 4 |

Here `train` means the 9,233 remaining original training rows and `dev` the 770
held-out rows. One word-token test group has conflicting labels: `test:2838`
and `test:618` differ in the spelling of “top ups”/“top-ups” and are labeled
card-charge and bank-transfer-charge respectively. The primary benchmark keeps
both official examples. These observations establish neither leaked evaluator
gold labels nor independence from encoder/head training data; training exposure
remains unknown.

Source: [PolyAI BANKING77 at the pinned revision](https://github.com/PolyAI-LDN/task-specific-datasets/tree/57ec275d8078af65b7731c2a98be812d844a6d6b).
Dataset excerpts and labels retain their [CC BY 4.0 attribution](../evaluation.md#dataset-and-task-contract)
to Iñigo Casanueva, Tadas Temčinas, Daniela Gerz, Matthew Henderson, and Ivan Vulić,
*Efficient Intent Detection with Dual Sentence Encoders* (2020),
[paper](https://aclanthology.org/2020.nlp4convai-1.5/).

## Interpretation boundaries

Prediction hashes detect inconsistent files. They cannot authenticate execution
or stop an author from fabricating observations and recomputing hashes. Source,
hardware, and runtime metadata are snapshots before execution, not continuous
monitoring. Caller metadata is not an attestation.

The mock campaign supports arithmetic, failure retention, validation, and report
generation in its tested scenarios. Mock hardware APIs support metadata/control
flow checks, not claims that real CUDA/MPS APIs have been exercised here. Different
real machines, runtime versions, resource exhaustion, and process kills can
expose additional issues. The [real-run protocol](../benchmark-protocol.md) retains
these remaining checks rather than labeling them as passed.

Maximum repeated-score drift is measured from the first successful attempt; it
is not maximum pairwise drift. Confidence intervals, statistical significance,
semantic duplicate removal, and competitor comparisons are not supplied by this
audit. The next model-quality claim requires actual retained model observations.
